v1.10.1
- A display that takes longer to boot than Kodi does is picked up on its
  own.  A Samsung frame needs about half a minute after power on, so the
  service started without it, built the renderer from the configured size
  and then rejected every frame as being the wrong size once the panel
  finally answered - which dropped the USB link again and left the frame on
  its "USB" screen until the service was restarted by hand.  Layout and
  canvas are now rebuilt for the size the display really reports
- While the box is starting up the display is looked for every few seconds
  instead of once per reconnect interval, so the picture appears seconds
  after the panel is ready instead of up to five minutes later.  The new
  "Start-up grace period" setting says how long that lasts (default 180 s)
- No warning popup while the display may still be booting; the first
  attempts only go into the log, and the warning follows if it is still
  missing when the grace period is over
- Samsung frames that answer the switch request while still booting and
  come back as a USB drive anyway are asked again instead of being given up
  on after a single try

v1.10.0
- Layouts for 1024x600: every bundled design now ships a third size, so the
  10 inch Samsung frames (SPF-105P, SPF-107H, SPF-1000P) get a layout drawn
  for their panel instead of an 800x480 one stretched over it.  The portrait
  design gains portrait-600x1024.json for a frame mounted on its side
- The layout setting still stores the name without a size; loading picks the
  variant that fits, so an existing setup keeps working after the update and
  a 10 inch frame simply gets the larger file
- tools/scale_layout.py keeps an exactly square box square.  Scaling 800x480
  to 1024x600 moves the two axes by 1.28 and 1.25, which was enough to turn
  the record on the "vinyl" layout, round cover art and icons into ellipses
- The width and height sliders step in 8 instead of 16 pixels, so 600 can be
  selected at all - it was unreachable from 64 in steps of 16, which blocked
  1024x600 for the network display and for "force size"

v1.9.0
- Codecs, HDR and resolution are shown as names instead of the raw ids Kodi
  hands out: H.265 instead of hevc, Dolby TrueHD instead of truehd_atmos,
  DTS-HD MA, Dolby Digital Plus, 7.1 instead of 8
- New field ${player.hdr}: Dolby Vision, HDR10+, HDR10, HLG or SDR, with
  ${player.hdr_short} giving DV for a panel that has no room for the rest
- New field ${player.spatial} names the object audio (Atmos, DTS:X, IMAX
  Enhanced), which Kodi only encodes in the codec id
- ${player.resolution} finally reads 2160p / 1080p / 576i.  Kodi answers
  "4K" for a 2160 line picture and a bare number for everything else, so a
  layout appending a "p" produced "4Kp"; the geometry now comes from the
  player process info.  ${player.resolution_long} gives 3840x2160p,
  ${player.resolutionname} gives 4K UHD
- New fields ${player.audio} and ${player.video} put the whole line
  together: "Dolby TrueHD Atmos 7.1" and "H.265 2160p Dolby Vision"
- Also new: ${player.videocodec}, ${player.channels_count},
  ${player.videowidth}, ${player.videoheight}, ${player.fps}, and the
  ${player.*_raw} fields for anyone who was matching on the raw ids
- The bundled default layouts show the dynamic range next to the resolution
  and the codec; the tables follow TinyPPI, so a box running both names a
  stream the same way on the television and on the panel

v1.8.1
- Preview rendering is about 17x faster: RGB565 is expanded to RGB by
  translating whole byte planes instead of walking the framebuffer pixel by
  pixel, which is what the browser editor waited for on every drag
- The Kodi data provider resolves the player state, the media type and
  /proc/meminfo once per frame instead of once per token; a page with a
  dozen player fields went from 36 visibility calls per frame to 3
- The service opens the data frame itself, so dimming and the frame rate
  keep reacting while the test pattern is on screen
- Cover art that is not there yet is looked for once every few seconds
  rather than on every frame
- The editor compares its password in constant time and closes the
  connection when it refuses an oversized request

v1.8.0
- New output mode "Network display": the service serves the rendered frames
  over HTTP instead of a USB panel, so any browser in full screen can be the
  display - a wall mounted tablet, a phone, a second monitor
- The page at /display is a plain <img> fed by a multipart/x-mixed-replace
  MJPEG stream: no WebSocket and no canvas, so it works on the old WebKit of
  an Android 4.x tablet; a little script only reconnects after a reboot
- /display/stream and /display/frame.jpg serve the raw stream and a single
  still; ?fit=fill stretches the picture to the whole screen
- The web interface password is accepted as ?key=... on the display
  endpoints, because a kiosk browser cannot answer a Basic auth challenge
  for a sub resource; the layout editor keeps its Basic auth
- The HTTP server always runs in network mode, independent of the editor
  switch, and the display size can be set without "override display size"
- Kodi shutdown pushes a black frame before the server stops, so a browser
  that stays open does not freeze on the last picture
- The JPEG encoder, the software dimming and their settings are shared with
  the Samsung frames

v1.7.0
- Layout editor in the browser: the service serves a drag and drop editor at
  http://<box>:8050/ where pages and widgets are placed with the mouse
- The preview beside it is drawn by the add-on's own renderer, so it shows
  exactly what the panel will show, with demo or live data
- Every widget property, data field and filter is offered in a catalogue
  generated from the renderer itself, in German and English
- Layouts are saved to the user's folder and can be sent to the panel from
  the editor; the bundled ones are shadowed, never overwritten
- New settings: editor on/off, port, reachable from the network or the box
  only, and an optional password
- tools/webeditor.py runs the same editor on a PC without Kodi

v1.5.0

v1.4.0
- Backlight settings reworked: the display now dims while nothing is playing
  instead of following the screensaver and an idle timer
- Samsung SPF frames got a brightness setting of their own - the picture is
  darkened in software, because the frames have no backlight command
- Fixed the AX206 brightness setting having no effect: every settings change

v1.3.0
- Eight more layouts, each in both display sizes:
  light (dark on white, for bright rooms), terminal (green monospace console),
  neon (magenta/cyan with a glowing outline), vinyl (the cover as a round
  record with a centre hole), nextup (what is playing and what comes next),
  weather (clock beside the weather, only shown when a weather add-on is set
  up), library (movies, shows and albums as large counters) and portrait
  (320x480 for a display mounted at 90 degrees)
- The line widget now fills its own box: a wide flat box draws a horizontal
  rule of that height instead of a one pixel vertical line, which is what
  everyone writing "w": 440, "h": 3 expects
- The 800x480 vinyl layout is hand made, because scaling the axes separately
  turns a circle into an oval

v1.2.0
- Five new layouts built for reading from a distance, in both display sizes:
  xl-player (40 px title, 38 px times), xl-remaining (the remaining time at
  96 px, the one number that matters during a film), xl-clock (128 px clock
  with what is playing underneath), xl-system (clock plus CPU, temperature
  and RAM as three large figures) and cover-full (artwork edge to edge with a
  slim info strip)
- Bundled font sizes up to 128 px, so large type stays crisp instead of being
  resampled from 64 px
- tools/scale_layout.py rescales a layout for a different display size,
  positions per axis and type sizes by height
- Fixed the IP address: some Kodi builds return the label name instead of an
  address, so the socket lookup is used first
- Fixed free space, which reported "0 MB" because the info label follows the
  GUI context; it is now read from the filesystem, with usedspace, totalspace
  and freespace_percent alongside it
- Demo data separates a film (director, no show title) from a TV episode
  (show title and S..E.., no director), so previews match reality

v1.1.1
- Start and stop commands: a shell command can be run when the service starts
  (before the display is opened) and when it stops (after the USB connection
  is released). Samsung frames have no power control in their protocol, so
  this is how a smart plug can switch them with the box
- Documented how to connect a Samsung frame and what can and cannot be done
  about switching it off

v1.1.0
- Samsung SPF photo frame support: SPF-72H, SPF-75H/76H, SPF-83H/83M,
  SPF-85H/85P, SPF-86H/86P, SPF-87H, SPF-105P, SPF-107H, SPF-700T, SPF-800P
  and SPF-1000P, including the switch out of USB mass storage mode, so no
  usb_modeswitch setup is needed
- Built-in baseline JPEG encoder, because the frames accept complete JPEG
  images only. A restart marker after every MCU row makes each row
  independently coded, so unchanged rows are copied from the previous frame's
  bitstream; flat blocks skip the DCT and repeated blocks are cached. A
  typical update re-encodes 2 to 6 of 30 rows
- Display type is a setting; JPEG quality and chroma subsampling configurable
- Layouts for 800x480 panels (default, big cover, minimal, dashboard), picked
  automatically when the selected layout name has a size specific variant
- Backlight settings apply to the AX206 only; on a Samsung frame, which has no
  backlight control over USB, "switch off when idle" shows a black picture
- Both drivers now raise a shared DisplayError and either kind of panel is
  reconnected automatically after it disappears from the bus

v1.0.1
- Fixed the service failing to start on CoreELEC with UnicodeDecodeError:
  layout files and the example layout are now read as UTF-8 (BOM tolerated)
  instead of relying on the C locale, whose default encoding is ASCII
- Fixed the configured USB device IDs being passed to the driver as a raw
  string, so the bus scan never matched and the add-on reported
  "no AX206 display found" even with a panel attached
- Fixed Kodi rejecting the empty default of the "User layout folder" setting
  (missing allowempty constraint)
- Service overrides are no longer lost when the settings are reloaded
- Self test covers the settings-to-display path and guards against text mode
  file reads without an explicit encoding

v1.0.0
- First release
- AX206 USB LCD support (USB ID 1908:0102) through libusb/ctypes, no extra
  Python modules required
- Only the changed part of each frame is sent to the panel
- JSON layout engine: pages with conditions and automatic rotation, widgets
  for text (scrolling, wrapping, shadow), progress bars (bar/segments,
  horizontal/vertical, knob), graphs, rectangles, lines, circles, images,
  icons and an analogue clock
- Access to every Kodi InfoLabel and boolean condition, plus player, system,
  weather and library data with a filter pipeline
- Bundled layouts: Default (music/video/clock/system), Big Cover, Minimal,
  Dashboard
- Built-in PNG and baseline JPEG decoders with scaled IDCT for fast cover art
- Anti-aliased DejaVu bitmap fonts in any size
- Rotation 0/90/180/270, mirroring, configurable pixel byte order
- Backlight control: dim on screensaver, switch off when idle, clear on exit
- Kodi notifications mirrored on the panel
- Menu and remote-control actions: choose layout, preview, next page, test
  pattern, status, reload, brightness
- Preview mode and tools/preview.py to design layouts without hardware
- tools/selftest.py verifies fonts, decoders, USB protocol and all layouts
- English and German translations
